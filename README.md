# 红中赖子杠（七皮四赖 · 武汉麻将）

原生 JavaScript（ES Modules）+ SVG 牌面的单机四人麻将，附一套可复现的 AI 策略实验台。

- **单文件、断网可玩**：构建产物是一个 HTML 文件，双击即开，电脑和手机共用同一份，布局自动适配。
- **对手可配**：三家电脑可分别设为「稳健」或「精算」，两者都经复式对局实测强于引擎基线。
- **离线建议**：本地计算向听、进张与危险度，不联网。
- **大模型提问（可选，默认关）**：用你自己的 API 密钥直连模型，问「为什么这样打」。

## 一、快速开始

### 1. 直接玩

双击 `dist/hongzhong-mahjong.html`，用 Edge / Chrome 等现代浏览器打开。你操作南家，另外三家是电脑。

`dist/红中牌室-手机版.html` 与它**字节相同**，只是换了个文件名方便发到手机。

### 2. 开发

```powershell
npm start          # = node server.mjs，访问 http://127.0.0.1:4173
npm test           # = node --test，38 项
npm run build      # = node build.mjs，生成 dist/hongzhong-mahjong.html
```

- 地址栏追加 `?seed=123` 可复现同一开局；重开时保持该种子。
- `server.mjs` 除静态文件外还提供 `/llm` 转发端点（见 [3.2](#32-大模型提问)），纯静态使用时不需要它。

### 3. 策略实验

```powershell
# 复式对局：每个牌局块跑 24 种座次排列
node run_arena.mjs --lineup Guarded,Efficient,Tempo,Closed --mode duplicate --blocks 240

# 分片并行后合并
node run_arena.mjs --lineup ... --shard 3 --of 12 --out part3.json
node run_arena.mjs --merge part0.json,part1.json,... --title 合并结果
```

可选策略见 `strategies_real.mjs` 的 `REAL_STRATEGIES`（Apex / Balanced / Efficient / Guarded / Closed / Tempo）与 `simulate_tournament.mjs` 的旧版原型（Greedy / Menqian / QiDui 等）。`--profiles '{"G_d0":{"base":"Guarded","defense":0}}'` 可临时注册调参变体。

## 二、完整规则

### 1. 牌数与开局

- **用牌**：136 张（万、条、筒各 1–9 共 108 张 + 东南西北中发白各 4 张共 28 张），无花牌。
- **起手**：庄家 14 张，闲家 13 张，逆时针行牌。
- **王牌**：固定留 **14 张**不可摸（含指示牌），可摸牌 **69 张**。杠后从王牌补牌，牌墙尾部回补一张进王牌——每开一个杠，可摸的牌就少一张。牌墙摸完即荒庄。
- **翻指示牌定皮赖**：
  - 发牌后翻一张**指示牌**；翻到红中则回墙重翻。
  - **赖子**（4 张）：指示牌的**下一张**。数字牌在本花色 1–9 循环（翻 9 万 → 赖子 1 万）；字牌按 东 → 南 → 西 → 北 → 发 → 白 循环，跳过红中。
  - **皮子**：指示牌同种牌 + 红中。

### 2. 特殊牌

- **赖子（万能牌）**
  - 可代替皮子以外的任意牌组成顺子、刻子、将；
  - 可单张开**赖杠**（自身 ×4，从王牌补牌），也可打出，但打出的赖子别人不能吃碰杠胡；
  - **两赖禁屁胡**：手持两张及以上赖子不能胡屁胡，胡家自身倍数达到封顶后解除。
- **皮子**
  - 不能代替任何牌，不能吃碰杠，只能留手或单张开**皮杠**（自身 ×2，从王牌补牌）；
  - **手上有皮不能胡**。

### 3. 胡牌条件

1. 手上无皮；
2. 不是「两赖屁胡」（已达封顶除外）；
3. 至少一家付款者的打点达到 **4**；
4. 屁胡须 **2、5、8 将**；七对与大胡的将牌、赖子张数不限——**杠上开花例外**，它按大胡计倍数与付款范围，但将牌仍须 2、5、8。

门前清可以胡；胡家开口不加倍。

### 4. 算分

$$\text{付款} = \min(\text{封顶},\ W_{\text{胡家}} \times M_{\text{输家}}) + \text{顶外半顶}$$

**胡家倍数 $W$**（连乘）

| 项 | 倍数 |
|---|---|
| 七对 | ×4 |
| 豪华七对（以实际四张相同牌为准，替代普通七对） | ×8 |
| 每个大胡（碰碰胡、清一色、将一色、风一色、全求人、海底捞等，可叠加） | ×8 |
| 杠上开花（算大胡，只在自摸时成立） | ×4 |
| 硬胡（无赖，或赖全部还原为本身） | ×2 |
| 每个普通杠 / 皮杠 | ×2 |
| 每个赖杠 | ×4 |

杠上开花时触发它的那个杠照常计番：普通杠或皮杠 + 杠上开花 = **×8**，赖杠 + 杠上开花 = **×16**。

**输家倍数 $M$**：开口（吃 / 碰 / 明杠）×2；每个普通杠 / 皮杠 ×2；每个赖杠 ×4。

**付款范围**

- 屁胡点炮：仅点炮者付；
- 七对、大胡点炮：三家付；
- 自摸：逐家算。

每家独立判断是否达到 4，不足则不付。

**封顶**：可选 10 / 20 / 30 / 40 / 50。**金顶**只在三家付款的局面（自摸、七对、大胡）且胡家自身倍数达到封顶时成立，未开口的付款者在顶外另付半顶；点炮屁胡只有点炮者一家付，倍数再高也不算金顶、没有顶外半顶。

### 5. 鸣牌与其他

- 仅下家可吃；胡 > 碰杠 > 吃。
- 一炮单响，从庄家起逆时针取第一个胡家。
- 只有蓄杠可被抢；暗杠、皮杠、赖杠不算开口，皮赖杠不占组。
- 海底捞：正常摸牌或补摸后余墙 ≤ 4 张。
- 庄家胡或荒庄连庄。

## 三、界面功能

### 3.1 离线建议

工具栏「建议」开关，默认关，打开需要输入四位数密码（输对一次后本标签页内记住，刷新或关掉标签页要重输）。密码在源码里只存加盐哈希、看不到明文，但静态网页防不住懂前端的人——改一行代码就能绕过，四位数的哈希也能瞬间穷举，所以它只是「防君子」的锁。另外大模型面板会把建议数据一起交给模型，要彻底锁住需要连它一起锁。完全本地计算，数字来自 `handeval.mjs`（见 [4.2](#42-向听引擎)），`advisor.mjs` 只负责翻译成人话。

- 建议表只列 3 行；
- **不给杠的硬建议**：有杠可开时照常给出牌建议，末尾附一句「或者开皮杠 中」。杠是取舍（×2/×4 与补牌 ↔ 自身赔付也翻倍、可能搏杠上开花），不替你决定；
- 硬性提醒单列：手上有皮、两张赖子、没有 2/5/8 将、有人推得很凶。
- **听牌与 1 向听时列出具体的牌**：听牌时列出听哪几张、各剩几张、共几张，用完整胡牌判定标出「牌型听了但打点不够 4、胡不了」的牌（最常见：没人开口也没杠，硬屁胡每家只付 2 点）；1 向听时列出摸到就能听牌的牌与剩余张数。赖子标成「赖子×」。

### 3.2 大模型提问

工具栏「大模型」开关，**默认关**。关着时页面不发出任何网络请求。

打开后可以就当前局面提问（留空默认问「为什么建议这样打」），支持一局内多轮追问，换局清空对话。提示词在 `coach.mjs`，把局面（只含你能看到的信息）和离线建议一起交给模型。

**设置与排错**

- **测试连接**：用弹窗里正在填的值（不必先保存）发一条极短请求，显示往返耗时或具体错误（密钥无效、模型名不对、网络不通……），走的路径与正式提问完全相同。
- **超时**：提问 120 秒、测试 45 秒没有返回就报错，不会一直停在「正在思考」；等待时显示已等秒数和实际连接的地址。
- **接口地址写法**：只填域名会自动补版本路径（多数为 `/v1`，Gemini 为 `/v1beta`）；带路径的照原样用（如 `https://dashscope.aliyuncs.com/compatible-mode/v1`、`https://open.bigmodel.cn/api/paas/v4`）；把完整接口地址整条粘进来、漏写 `https://` 也能识别。弹窗里实时显示「实际请求」的完整地址。
- **输出格式**：界面按纯文本显示，不渲染 Markdown。提示词要求模型只输出纯文本，显示前再兜底去掉漏出来的 `**`、`#`、列表符号。

**服务商**：`llm.mjs` 内置 Anthropic Messages、OpenAI Chat Completions / Responses、Gemini、xAI 五种协议，均实测允许浏览器从 `file://` 直接调用，因此单文件 HTML 双击打开就能用。每家都可以改接口地址，接自建中转或国内镜像。国内厂商是否允许浏览器直连尚未测试；不允许时改走中转，或用 `node server.mjs` 打开页面并勾选「走本地转发」。

**密钥去哪了**

- 只存在**你这台设备、这个浏览器**的 localStorage 里，不会写进 HTML 文件，构建也不会打包它。
- 把 HTML 发给别人，对方看到的是空配置，需要填自己的密钥。
- 设置弹窗里有「清除密钥」。
- 用 `server.mjs` 转发时，可在服务端设环境变量 `HZ_KEY` 或 `HZ_KEY_<服务商>`，页面里密钥留空，密钥完全不进浏览器。

**提示词的两条经验**

- 模型答非所问，根因多半在提示词。曾经问「不杠、等听牌再杠搏杠上开花行不行」，模型答「不行」——因为建议面板写的是「摸到只能杠」，提示词又声称引擎输出是权威。实测 1,763 个回合里 `skinKong` 和 `discard` 同时可用，是措辞本身错了。
- 「请直接引用数字」+「三到五句话」会把模型逼成复读机，回答和离线建议几乎没有区别。现在的提示词要求模型自检「把数字划掉之后还剩什么」。

### 3.3 对手策略

「对手」按钮为三家分别选「稳健 / 精算」，存 localStorage 的 `hz.ai.seat.<座位号>`。策略是只读 state 的纯函数，中途换人下一次决策即生效，不用重开。

### 3.4 牌局反馈

- **牌局动态**：吃 / 碰 / 杠 / 放炮全部进日志，默认显示最新三手，可滚动回看。
- **鸣牌提示**：别人吃碰杠时在对应座位闪一下（`#call-flash`），杠会区分皮杠 / 赖杠 / 暗杠 / 蓄杠；连续鸣牌不排队，只显示最新一次。
- **和牌横幅**：自摸 / 点炮 / 荒庄 / 你和牌四种形态，显示和张、番型和逐家分数变动，点一下进结算。庆祝分三档：
  - 普通：原样横幅；
  - **大胡，或总收入 ≥ max(封顶, 30) 点**（50 封顶即 ≥ 50，20 封顶按 30 算）：金边大卡、番型标签、总分滚动、彩带（大胡另有「大 胡」标签）；
  - **金顶**（三家付款的自摸、七对或大胡，且胡家自身倍数达到封顶）：金色主题、旋转光芒、更多彩带，逐家标出谁付了顶外半顶。
  - 三档都不自动消失，点一下才关。
- **比赛制**：每人 300 点起，任意一家跌破 0 分本场结束，横幅之后直接弹出本场排名（同分同名次，显示相对起始分的盈亏），可以回看本局结算或「再来一场」。「新牌局」也会重新从 300 点开始。
- 地址加 `?debug` 会暴露 `window.__hzDebug`（`announceWin`、`showRanking` 等），用来直接预览各档横幅与排名，正常游戏不受影响。
- **王牌**：侧栏「王牌 / 摸不到的牌」可展开查看。

### 3.5 行牌节奏

按动作分档（`app.mjs` 的 `thinkDelay`），而不是固定间隔：

| 动作 | 基准 | 抖动 |
|---|---|---|
| 过 | 90 × speed | ×0.7~1.3 |
| 吃碰杠 | 300 × speed | ×0.7~1.15，15% 概率 ×1.7~2.4（长考） |
| 出牌 | 420 × speed | 同上 |

「从容」档实测每手最短 1.08 s / 中位 2.14 s / 最长 4.03 s。随机数只决定等多久，动作在计时前已算完，**牌局走向仍只由种子决定**。

### 3.6 声音

工具栏「声音」打开设置：人声、落牌声默认开，环境声默认关，另有总音量和四家嗓音试听。浏览器要求先有一次点击或按键才能出声，所以打开页面不会突然响。

- **人声播报**：打牌报牌名，鸣牌喊「吃 / 碰 / 杠 / 赖子杠」（明杠、蓄杠、暗杠、皮杠都只喊「杠」），和牌只喊三句——杠上开花喊「杠开」，其余自摸（含海底捞）喊「自摸」，胡别人的牌（含抢杠）喊「胡了」；荒庄由旁白播报。四家各一种嗓音，并按座位左右摆位，不看屏幕也知道是谁。新的叫牌会打断正在念的牌名，牌名不会打断叫牌。人声开着时，电脑出牌和吃碰杠会等上一段播报念完再动，快局下也不会把牌名吞掉。胡牌类喊声音调更高、语气更重，播放时再加 4 dB，总输出有限幅器防止削顶。
- **落牌声**：四种真实牌声随机轮换，每次微调音高和音量，避免机械重复；新局播洗牌声。
- **环境声**：真实牌室录音截出的 40 秒无缝循环，压得很低，只作垫底；切到别的标签页时自动暂停。

### 3.7 手机适配

`dvh` 单位、44px 最小点击区、`touch-action: manipulation`、操作栏 sticky、横屏单独断点（`max-height:560px and orientation:landscape`）、`prefers-reduced-motion`。

手机直接打开本地 HTML 文件时，部分系统（iOS「文件」预览、部分安卓浏览器）可能限制脚本或网络请求。最稳的做法是把 HTML 放到任意 https 静态托管上，用链接打开。

## 四、策略研究

### 4.1 实验方法

早期版本的实验（固定坐次、按大局计样本、不控制发牌）不成立，结论也未能复现，已整体作废，详见 [4.8](#48-旧版实验为什么作废)。现在的实验台（`arena.mjs` / `run_arena.mjs`）：

- **复式对局（duplicate）**：固定一副牌的种子，把四个策略在 **24 种座次排列**上全跑一遍。每副牌每个策略都当过每个位置，坐次优势和发牌运气被完全抵消。
- **分块 bootstrap**：置信区间在独立的「牌局块」上重采样，不在小局上重采样（同一副牌的 24 个排列彼此不独立）。

### 4.2 向听引擎

`handeval.mjs`：

- 标准型 / 七对 / 碰碰胡三路取最优，赖子当万能牌，带 2/5/8 将约束；
- 进张按获取来源加权：能碰的牌三家都可能打出（`pongW`），只能吃的牌只有上家会给（`chiW`）；
- 在 22,255 个局面上与引擎的 `fastCanWin` / `fastWaits` 对拍，**0 处不一致**。

### 4.3 修复前的强度

下表是进张口径修复（见 [4.4](#44-进张口径修复)）之前测的，每小局净分，95% bootstrap CI（已计入王牌）：

| 策略 | 对 3 家引擎基线 | 强手同桌 |
|---|---|---|
| **稳健 Guarded** | +2.52 [+0.92, +4.15] | **+1.56 [+1.06, +2.05]** |
| **精算 Efficient** | **+3.27 [+1.59, +4.97]** | +0.78 [+0.33, +1.24] |
| 引擎基线 `aiChoose` | 0（基准点） | −1.64 [−2.32, −0.97] |
| 纯速度流（已淘汰） | −0.15 [−1.60, +1.39] | −0.70 [−1.23, −0.17] |

两者共用同一套向听—进张—安全度评估，差别只在鸣牌闸门与避炮：

- 稳健：放炮率 13.6%、开门率 68.9%，两项都更低；
- 精算：不避炮，进张更快，胡牌率略高。

修复前的数据显示对手弱时精算更优、对手强时稳健更优；修复后这个交叉没有复现，见 4.4。

王牌使可摸牌从 82 张降到 69 张，巡数变少，推牌的边际收益下降、放炮代价相对上升，排名因此变化；**加王牌前的数字已作废**。杠上开花规则改动后重跑，所有策略净分变化在 ±0.06 以内，排名不变；「放宽开杠去搏杠上开花」实测不划算（−0.24）。

### 4.4 进张口径修复

**问题**：出牌排序用的向听给七对（+1.5）、碰碰胡（+1.0）加了折价，但数有效牌时用的是未折价的向听。两把尺子不一致：打掉孤张后，未折价的七对恰好领先，有效牌就只数能凑对子的牌，把屁胡路线的进张全漏掉，结果「拆对子」反而显得比「打孤张」进张多。

实战牌例（五筒是皮）：二万 六万 二条 三条 三条 五条 九条 三筒 南 南 白 白 + 摸一筒。旧口径推荐打三条（13 种有效牌），打九条只算出 6 种；统一口径后打九条 12 种、打三条 8 种，孤张九条才是该打的牌。建议面板与稳健、精算两个电脑对手共用这套评分，都受影响。

**修复**：`handeval.mjs` 的 `ukeire` 接受 `opt.shanten`，建议面板与策略都传入自己的折价向听；策略侧由 `ukConsistent` 开关控制，现为默认开。回归测试见 `handeval.test.mjs`。

**实测**（复式对局，块配对 bootstrap 95% CI，修后减修前，每小局净分；强手同桌为修前稳健、修后稳健、修前精算、修后精算互打，400 副牌 × 24 座次 = 9,600 小局；对基线为同种子配对，各 240 副牌 × 24 座次）：

| 场景 | 封顶 | 稳健 | 精算 |
|---|---|---|---|
| 强手同桌 | 32 | **+1.00** [+0.47, +1.59] | **+1.14** [+0.51, +1.89] |
| 强手同桌 | 50 | **+1.26** [+0.56, +1.93] | **+1.56** [+0.70, +2.51] |
| 对 3 家引擎基线 | 32 | **+1.38** [+0.48, +2.34] | **+1.11** [+0.10, +2.26] |
| 对 3 家引擎基线 | 50 | **+1.54** [+0.46, +2.79] | +1.23 [−0.08, +2.70] |

实验台默认封顶已改为 50（与游戏默认一致）。下表是修复后在 32 封顶下的绝对强度：

| 策略 | 对 3 家引擎基线 | 四者同桌 | 胡牌率 | 放炮率 | 开门率 |
|---|---|---|---|---|---|
| 精算（修后） | **+4.37** [+3.15, +5.92] | **+0.74** [+0.30, +1.12] | 26.0% | 18.5% | 69.7% |
| 稳健（修后） | +2.20 [+0.80, +3.83] | +0.33 [−0.02, +0.77] | 24.6% | 15.5% | 68.8% |

两点说明：

- 这次对基线实验里，修前稳健测得 +0.82 [−0.47, +2.20]，低于 4.3 表中的 +2.52。两次用的种子不同，置信区间重叠，属于抽样波动；比较修复效果要看同种子配对的差值，而不是跨实验比绝对值。
- 4.3 表里「对手强时稳健更优」的交叉，在这组阵容里没有复现：修后精算在两种场景下都领先稳健。稳健的放炮率仍然低 3 个百分点，但这部分没有换来净分。

复现：`run_arena.mjs --profiles '{"GuardedOld":{"base":"Guarded","ukConsistent":false}}' ...`（现在默认已开，旧口径用 `"ukConsistent":false` 注册）。

### 4.5 试过但没有采用的打法

以下都在 50 封顶下用同样的复式方法测过（留皮一直留到听牌那一版也测了 32 封顶），开关保留在 `strategies_real.mjs`，默认关闭。

**同分时先打「最没用」的牌**（`tieKeep`）：出牌评分并列时，先打字牌和幺九，2/5/8 最后动，而不是按手牌顺序。对电脑对手没有可测出的影响（32 封顶，四组差值的 CI 都跨 0，强手同桌略偏负），所以策略里不启用。建议面板保留了这条裁决，只为不在并列时推荐与它自己提醒相矛盾的 2/5/8 单张。

**最后一张皮子留到听牌才杠，搏杠上开花**（`holdLastSkin`）：皮子多于一张时照杠，最后一张等其余 13 张听牌再杠，补牌那一下就是一次杠开机会。杠开一定三家付，50 封顶下每次约 110 分，是点炮胡（约 20 分）的 5 倍多；但留着皮不能胡，也就不能接炮。

| 版本 | 杠开 · 每千局 | 强手同桌（留皮 − 即杠） | 对 3 家基线（留皮 − 即杠） |
|---|---|---|---|
| 一直留到听牌 | 10 → 34 | 稳健 +0.73 [−0.49, +1.84]，精算 −0.28 [−1.89, +0.96] | 稳健 −1.29 [−3.88, +1.44]，精算 −1.69 [−4.21, +0.28] |
| 只在 1 向听时留（`holdSkinMaxXt: 1`） | 约 +40% | 稳健 +0.54 [−0.20, +1.02]，精算 −0.08 [−0.77, +0.77] | 稳健 +0.06 [−0.93, +1.05]，精算 +0.17 [−0.59, +1.04] |
| 2 向听以内就留（`holdSkinMaxXt: 2`） | 约 ×2 | 稳健 +0.23 [−1.05, +0.93]，精算 −0.41 [−1.56, +0.66] | 稳健 −0.13 [−1.50, +1.88]，精算 −1.19 [−2.54, +0.27] |

一直留到听牌时，以稳健强手同桌为例，每千局多出 23 次杠开约 +2,440 分，但少了 80 次点炮胡、37 次普通自摸，共约 −3,160 分；少杠皮让自己输牌时的赔付倍率从 8.1 降到 5.2，付出少了约 1,660 分，净分才勉强持平。「只在 1 向听时留」把不能接炮的时间压到最短，亏损基本消失，但也没有测出确定的提升。

### 4.6 调试过程中定位的问题

第一版策略输给了引擎基线，逐个定位出三个 bug：

1. **多路线取 min**：成牌路线的评估取了最小值而非按价值加权，高价值路线被抹掉；
2. **威胁计数把强制皮杠算进去**：皮杠是强制的（有皮不能胡），不代表对手在推牌。修正见 `handeval.mjs` 的 `threatOf`；
3. **`ukWeight` 标定错误**：进张项 `uk.tiles*6` 实战中是 150~360，而一步向听值 200，权重 1.0 会让进张项压过向听项。降到 **0.3** 后，净分从 **−4.08 变为 +2.28**。

2×2 消融（鸣牌闸门 开/关 × 出牌逻辑 新/引擎）：对照组 `callall_eng` 精确复现基线（净分 0.00、胡牌率 25.0%），说明实验台本身无偏；闸门成本 ≈ 0，出牌逻辑成本 = −4。问题在出牌逻辑，不在闸门。

### 4.7 站得住的原则

没有通用最优策略，实测能站住的只有四条：

1. **皮子是硬约束**：手上有皮不能胡，什么时候杠可以选，但胡之前必须杠掉；
2. **两张赖子必须处理**：两赖禁屁胡，开赖杠既解禁又拿 ×4，是全场收益最高的单一操作；
3. **鸣牌看向听是否真的下降**：开门会让你输牌时的赔付 ×2，向听不降的鸣牌是净亏；
4. **进张是配角**：权重 0.3。向听决定能不能胡，进张只决定快多少。

### 4.8 旧版实验为什么作废

旧版 README 用 `simulate_tournament.mjs` / `run_experiments.mjs` 跑了 7 个原型策略（Greedy、Menqian、QiDui、KongHunter、AdaptiveValue、Championship、Predator）共 120 场大局，得出「吃碰速攻是统治级最优解」「防守是慢性自杀」等结论。它的设计有三个问题：

| 问题 | 后果 |
|---|---|
| 固定坐次 | 只有下家能吃，坐次本身就值几分，混进了策略差异 |
| 样本按大局计、未分块 | 独立单元远少于表面数字，没有置信区间就无法判断差异是否真实 |
| 未控制发牌 | 不同策略跑在不同牌上，赢的可能只是牌好 |

三条叠加，足以让任意两个强度接近的策略排出任意顺序。在复式实验台下，纯速度流对引擎基线的净分是 −0.15（CI 跨零），结论不成立。旧代码保留在仓库里，供复查，不再作为依据。
