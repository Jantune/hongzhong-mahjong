# 红中赖子杠（七皮四赖 · 武汉麻将）

原生 JavaScript（ES Modules）+ SVG 牌面的单机四人麻将。你坐南家，另外三家是电脑。

- **单文件、断网可玩**：构建产物是一个 HTML 文件，双击即开，电脑和手机共用，布局自动适配。
- **三档电脑对手**：简单 / 困难 / 激情，每家可单独设置，均经复式对局与锦标赛标定。
- **离线建议**：本地计算向听、进张与危险度，不联网。
- **大模型提问（可选，默认关）**：用你自己的 API 密钥直连模型，问「为什么这样打」。
- **策略实验台**：复式对局 + 分块 bootstrap，可复现地比较策略强度。

## 快速开始

需要 Node.js 22 以上，无第三方依赖。

```bash
npm run build   # 生成 dist/hongzhong-mahjong.html（单文件，双击即玩）
npm start       # 开发服务器 http://127.0.0.1:4173，端口可用环境变量 PORT 改
npm test        # 单元测试
```

- `dist/红中牌室-手机版.html` 与主文件字节相同，只是方便发到手机的文件名。
- 地址栏加 `?seed=123` 可复现同一开局，重开时保持该种子；加 `?debug` 暴露 `window.__hzDebug`，用于预览和牌横幅、排名等界面。
- 手机直接打开本地 HTML 时，部分系统会限制脚本或网络请求；最稳的做法是放到任意 https 静态托管上用链接打开。

## 规则

### 牌数与开局

- **用牌**：136 张（万、条、筒各 1–9 共 108 张，东南西北中发白各 4 张共 28 张），无花牌。
- **起手**：庄家 14 张，闲家 13 张，逆时针行牌。
- **王牌**：固定留 14 张不可摸（含指示牌），可摸牌 69 张。杠后从王牌补牌，牌墙尾部回补一张进王牌，所以每开一个杠可摸的牌少一张。牌墙摸完即荒庄。
- **翻指示牌定皮赖**：发牌后翻一张指示牌，翻到红中则回墙重翻。
  - **赖子**（4 张）：指示牌的下一张。数字牌在本花色 1–9 循环（翻 9 万 → 赖子 1 万）；字牌按 东 → 南 → 西 → 北 → 发 → 白 循环，跳过红中。
  - **皮子**：指示牌同种牌 + 红中。

### 特殊牌

- **赖子（万能牌）**
  - 可代替皮子以外的任意牌组成顺子、刻子、将；
  - 可单张开**赖杠**（自身 ×4，从王牌补牌），也可打出，但打出的赖子别人不能吃碰杠胡；
  - **屁胡最多一张赖子当万能牌**：多出的赖子只能当它本身的牌用，这样组得成就能胡；两张都得当万能牌才组得成的屁胡不能胡。大胡（含七对、杠上开花）不受限。
- **皮子**
  - 不能代替任何牌，不能吃碰杠，只能留手或单张开**皮杠**（自身 ×2，从王牌补牌）；
  - **手上有皮不能胡**。

### 胡牌条件

1. 手上无皮；
2. 屁胡最多一张赖子当万能牌；
3. 至少一家付款者的打点达到 **4**；
4. **将一色是乱将**：手牌连同副露全是 2、5、8 就能胡，不看牌型（赖子可当任意 2、5、8；吃过就做不成）；
5. 屁胡须 2、5、8 将；大胡（含七对）的将牌、赖子张数不限。杠上开花例外：按大胡计倍数与付款范围，但将牌仍须 2、5、8；
6. **门前清的软屁胡只能自摸，不能捉铳**（抢杠也不行）。软屁胡指用了赖子当万能牌；硬屁胡门清也能捉铳。吃、碰、明杠（含补杠）才算开口，暗杠、皮杠、赖杠不算。大胡（含七对）门清也能捉铳。

### 算分

$$\text{付款} = \min(\text{封顶},\ W_{\text{胡家}} \times M_{\text{输家}}) + \text{顶外半顶}$$

**胡家倍数 $W$**（连乘；胡家开口不加倍）

| 项 | 倍数 |
|---|---|
| 七对（算大胡） | ×4 |
| 豪华七对（以实际四张相同牌为准，替代普通七对） | ×8 |
| 每个大胡（碰碰胡、清一色、将一色、风一色、全求人、海底捞等，可叠加） | ×8 |
| 杠上开花（算大胡，只在自摸时成立） | ×4 |
| 硬胡（无赖，或赖全部还原为本身） | ×2 |
| 每个普通杠 / 皮杠 | ×2 |
| 每个赖杠 | ×4 |

杠上开花时触发它的那个杠照常计番：普通杠或皮杠 + 杠上开花 = ×8，赖杠 + 杠上开花 = ×16。

**输家倍数 $M$**：开口（吃 / 碰 / 明杠）×2；每个普通杠 / 皮杠 ×2；每个赖杠 ×4。

**付款范围**：屁胡点炮仅点炮者付；大胡（含七对）点炮三家付；自摸逐家算。每家独立判断是否达到 4，不足则不付。

**封顶**可选 10 / 20 / 30 / 40 / 50。**金顶**只在三家付款的局面（自摸、大胡含七对）且胡家自身倍数达到封顶时成立，未开口的付款者在顶外另付半顶；点炮屁胡没有金顶。

### 鸣牌与其他

- 仅下家可吃；胡 > 碰杠 > 吃。一炮单响，从庄家起逆时针取第一个胡家。
- 蓄杠（补杠）：碰过的刻子，自己摸牌后的回合手里有第四张就能补；刚碰完还没摸牌时不能补。
- 只有蓄杠可被抢；皮赖杠不占组。
- 海底捞：正常摸牌或补摸后余墙 ≤ 4 张。
- 庄家胡或荒庄连庄。

## 界面功能

### 电脑对手

「对手」按钮为三家分别选难度，也可一键统一；默认困难，中途换人下一次决策即生效。托管（南家）固定用纯精算。

| 档位 | 打法 | 对 3 家引擎基线（每小局净分，95% CI） | 锦标赛平均名次 |
|---|---|---|---|
| 困难 | 精算 + 碰碰胡、七对、将一色路线 + 灵活赖杠；两张赖子以上时大胡慢一步也做 | **+6.13** [+5.07, +6.76] | 2.305 |
| 激情 | 大胡风格：七对 / 碰碰胡 / 清一色 / 将一色整局慢一步也做 + 灵活赖杠 + 最后一张皮子 1 向听时才杠、搏杠上开花 | +4.91 [+4.40, +5.83] | **2.243** |
| 简单 | 纯精算 | +3.63 [+2.58, +4.17] | 2.816 |

普通对局里困难最强；锦标赛里激情与困难打平，两者都明显强于简单。激情胡牌率只有两成左右，但近一半是大胡。

### 离线建议

工具栏「建议」开关，默认关，打开需输入四位数密码（只是「防君子」的锁：静态网页里改一行代码就能绕过）。完全本地计算，与困难档同一口径。

- 列出最优的几张打法及其向听、进张；并列最优的全部列出；
- 不替你决定杠：有杠可开时照常给出牌建议，末尾附一句「或者开皮杠 中」。两个例外——两张赖子以上且少一张万能牌不变慢时建议开赖杠；最后一张皮子、其余已听牌时建议先开皮杠，并标出杠上开花的牌；
- 听牌与 1 向听时列出具体的牌和剩余张数，标出「牌型听了但打点不够 4」和「门清只能自摸」的牌；
- 硬性提醒：手上有皮、两张赖子、没有 2/5/8 将、有人推得很凶。

### 大模型提问

工具栏「大模型」开关，默认关，关着时页面不发出任何网络请求。打开后可就当前局面提问、多轮追问，模型只拿到你能看到的信息和离线建议。

- **服务商**：内置 Anthropic Messages、OpenAI Chat Completions / Responses、Gemini、xAI 五种协议，均可从 `file://` 直接调用；接口地址可改，用于中转或镜像。只填域名会自动补版本路径，弹窗里实时显示实际请求地址。
- **测试连接**：用弹窗里正在填的值发一条极短请求，显示耗时或具体错误。提问 120 秒、测试 45 秒超时。
- **密钥**只存在本机浏览器的 localStorage 里，不会写进 HTML，也不会被构建打包；弹窗里可一键清除。
- 不允许浏览器直连的服务商，用 `npm start` 打开页面并勾选「走本地转发」；可在服务端设环境变量 `HZ_KEY` 或 `HZ_KEY_<服务商>`，密钥完全不进浏览器。

### 牌局与比赛

- **牌局动态**：吃 / 碰 / 杠 / 放炮全部进日志；刚打出的牌从出牌那家滑过来并有方向指示；别人鸣牌时对应座位闪一下。
- **杠的按钮**：自己回合的皮杠、赖杠、暗杠、蓄杠点选那张牌后才出现；别人打牌时的明杠、吃、碰、胡直接显示。
- **和牌横幅**：显示和张、番型和逐家分数变动。大胡或高额收入有金边大卡与彩带，金顶另有专属效果。
- **比赛制（默认开）**：每人按本金起（默认 300 点，可改），任意一家跌破 0 本场结束并弹出排名。改本金即开新的一场；难度、封顶热更新。
- **行牌节奏**：按动作分档加随机抖动（每手约 1–4 秒），随机数只影响等待时长，牌局走向只由种子决定。
- **手机适配**：`dvh` 单位、44px 最小点击区、横屏单独断点、支持「减少动态效果」。

### 声音

工具栏「声音」打开设置：人声、落牌声默认开，环境声默认关，另有总音量和四家嗓音试听。浏览器要求先有一次点击或按键才能出声。

- **人声播报**：报牌名，鸣牌喊「吃 / 碰 / 杠 / 赖子杠」，和牌喊「杠开 / 自摸 / 胡了」。四家各一种嗓音并按座位左右摆位。
- **落牌声**：四种真实牌声随机轮换并微调音高音量；新局播洗牌声。
- **环境声**：牌室录音截出的无缝循环，切到别的标签页时自动暂停。

| 素材 | 来源 | 授权 |

| 牌室环境声 | Freesound [#347018](https://freesound.org/people/rasfrecci_w_donna/sounds/347018/) "mah_jong_parlor_outside" by rasfrecci_w_donna | CC0 |
| 人声 · 南家、北家、西家与旁白 | 微软神经语音（edge-tts）：晓晓（普通话）、云夏（普通话）、晓北（东北话） | 以微软相关条款为准 |

## 策略实验台

```bash
# 复式对局：每个牌局块跑 24 种座次排列
node lab/run_arena.mjs --lineup Guarded,Efficient,Tempo,Closed --mode duplicate --blocks 240

# 锦标赛（飞局）模式：300 起、跌破 0 出局
node lab/run_arena.mjs --lineup ... --mode bust --start 300 --bust -1 --maxRounds 200

# 分片并行后合并
node lab/run_arena.mjs --lineup ... --shard 3 --of 12 --out part3.json
node lab/run_arena.mjs --merge part0.json,part1.json,... --title 合并结果
```

- 内置策略见 `src/strategies_real.mjs` 的 `REAL_STRATEGIES`，`Baseline` 为引擎自带的 `aiChoose`。
- 游戏里的难度档与调参变体用 `--profiles` 注册，例如 `--profiles '{"Hard":{"base":"Hard"},"G_d0":{"base":"Guarded","defense":0}}'`。
- **方法**：固定一副牌的种子，把四个策略在 24 种座次排列上全跑一遍，坐次优势和发牌运气被完全抵消；置信区间在独立的牌局块上重采样（同一副牌的 24 个排列彼此不独立）。
- **向听引擎**（`src/handeval.mjs`）：标准型 / 七对 / 碰碰胡三路取最优，赖子当万能牌，带 2/5/8 将约束；进张按来源加权（能碰的牌三家都可能打出，只能吃的牌只有上家会给）。

实测站得住的几条原则：

1. **皮子是硬约束**：手上有皮不能胡，什么时候杠可以选，但胡之前必须杠掉；
2. **两张赖子别急着杠**：赖杠让自己输牌时也 ×4 赔，少一张万能牌不变慢才杠；
3. **鸣牌看向听是否真的下降**：开门会让输牌时的赔付 ×2，向听不降的鸣牌是净亏；
4. **进张是配角**：向听决定能不能胡，进张只决定快多少；
5. **速度为主，大胡可以慢一步**：为清一色放慢两步明显亏；七对、碰碰胡、将一色慢一步也做，在锦标赛里名次明显更好。按分数切换打法（落后保命或转激进）都不划算。

以上结论只在本项目的策略之间测过，没有对真人测过。

## 目录结构

```
index.html  style.css      页面与样式
src/
  game.mjs                 规则引擎、状态机、王牌、日志
  scoring.mjs              算分与倍数
  handeval.mjs             向听 / 进张 / 危险度
  strategies_real.mjs      参数化策略与难度档
  advisor.mjs              离线建议的计算与措辞
  llm.mjs  coach.mjs       大模型直连适配层与提示词
  app.mjs                  界面、交互、节奏、动画
  audio.mjs                人声、落牌声、环境声（Web Audio）
  tiles.mjs  tile-assets.mjs  牌面绘制与素材
test/                      单元测试（node --test）
lab/                       复式对局实验台
scripts/
  build.mjs                把模块与音频内联成单文件 HTML
  server.mjs               本地开发服务器与 /llm 转发
  build_tile_sprite.cjs    由 assets/tiles 生成 src/tile-assets.mjs
tools/                     语音包生成与素材整理（Python）
assets/                    牌面 SVG 与音频素材
```

**引擎接口**：`createGame({cap, seed, dealer, scores, round})`、`nextRound`、`legalActions(state, seat)`、`applyAction(state, action)`、`visibleState(state, seat)`、`aiChoose`、`autoStep`、`validateState`。`applyAction` 返回新状态、不改动入参；`visibleState` 只暴露该座位能看到的信息；发牌只由种子决定。
